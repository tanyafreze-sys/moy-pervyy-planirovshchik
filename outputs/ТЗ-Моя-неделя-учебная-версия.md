# Техническое задание на учебное веб-приложение «Моя неделя»

Версия 2.0. Дата подготовки - 11 октября 2026 года.

## 1. Статус и назначение

Документ заменяет исходное ТЗ версии 1.0 от 9 октября 2026 года применительно к учебному проекту. Основание - загруженный документ «Техническое задание на веб-сервис “Моя неделя”» и требование ограничить приложение тремя файлами.

Приложение помогает одному пользователю планировать неделю по работе, спорту, творчеству, отдыху и собственным сферам. Основной процесс - задать цели и ограничения, создать действия, получить варианты недели, отредактировать и подтвердить план, отмечать выполнение и просматривать итоги.

Все положения ниже являются требованиями к будущей реализации. Они не означают, что приложение уже разработано или проверено. Упрощения исходного документа зафиксированы в этом ТЗ.

## 2. Состав проекта и границы

Поставляемое приложение состоит строго из трёх файлов в одной папке.

| Файл | Назначение |
|---|---|
| `index.html` | Разметка, формы, диалоги, подключение CSS и JS |
| `style.css` | Все стили, состояния элементов и адаптация интерфейса |
| `script.js` | Данные, проверки, сохранение, планировщик, обработка действий и отображение |

Используются обычные HTML, CSS и JavaScript без фреймворков, сборки, установки пакетов и внешних библиотек. Скрипт подключается как обычный скрипт с `defer`, без загрузки модулей или данных через сеть. Изображения, шрифты, JSON-заготовки и другие дополнительные файлы для работы не требуются. Применяются системные шрифты; при необходимости значки встраиваются в HTML.

ТЗ, пользовательские JSON-выгрузки и отчёты о проверках не входят в три файла приложения и не требуются для его запуска.

Из проекта исключены:

- сервер, серверная база данных и серверные API;
- регистрация, авторизация, аккаунты и восстановление доступа;
- Google Calendar и любые внешние календари;
- Telegram, боты и внешние уведомления;
- фоновые процессы, очереди, service worker и выполнение при закрытой странице;
- автоматические и серверные резервные копии;
- запросы к ИИ по API, ключи и токены;
- синхронизация устройств, совместная работа и поддержка одновременного редактирования в нескольких вкладках;
- автоматический перенос невыполненного и автоматическое перестроение подтверждённого плана;
- зависимости задач, таймеры и учёт фактически затраченного времени;
- экспорт ICS, PDF и CSV, сложная аналитика и отдельное мобильное приложение.

Перенос выполняется через форму даты и времени. Перетаскивание не является требованием учебной версии. Встречи создаются вручную. Вместо напоминаний предусмотрен список предстоящих и просроченных действий на экране «сегодня», без уведомлений по таймеру.

## 3. Среда запуска и ограничения хранения

Основной сценарий запуска - открыть `index.html` в настольном браузере. При начале разработки фиксируются название и версия браузера, ОС и проверенный способ открытия. Приёмка проводится в этой среде, в обычном профиле браузера, в одной вкладке.

При открытии через `file:` требования к поведению localStorage не определены стандартом и могут различаться между браузерами. Поэтому универсальная сохранность при открытии файла с диска не обещается. Это подтверждает [документация MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

На первом этапе обязательно проверяются запись, чтение и сохранность данных после закрытия и повторного открытия страницы по тому же пути. Если проверка не проходит, среда не подходит для приёмки требований хранения. Нельзя скрыто добавлять сервер или объявлять проверку успешной.

При недоступном хранилище приложение показывает предупреждение, допускает работу в памяти и ручную JSON-выгрузку, но не сообщает об успешном постоянном сохранении. Этот режим не считается выполнением требования localStorage.

Данные относятся к выбранному браузеру и профилю. Перемещение файлов, смена браузера и очистка его данных требуют предварительной выгрузки и последующего импорта. Приложение не заявляет защиту данных от других людей с доступом к этому профилю.

Интерфейс русский, неделя начинается с понедельника. Основные проверяемые ширины - 1280 и 1920 пикселей. При меньшей ширине допускаются перестроение элементов и горизонтальная прокрутка календаря, но кнопки и формы должны оставаться доступными.

## 4. Архитектура и сохранение

Все логические части находятся внутри `script.js` и выделяются функциями или объектами:

1. модель данных и начальные настройки;
2. проверка полей и связей;
3. чтение и запись localStorage;
4. проверка расписания;
5. построение вариантов;
6. учебный помощник;
7. расчёт итогов и история;
8. JSON-экспорт и импорт;
9. отображение и обработчики интерфейса.

Проверка расписания вызывается независимо от планировщика, в том числе после ручного редактирования. Помощник создаёт предложения, но не записывает задачи без принятия пользователем.

Всё состояние хранится одним JSON-документом под ключом `myWeek.state.v1`. Документ содержит версию формата, ревизию данных, настройки и коллекции объектов. Каждое действие сначала формирует и проверяет новое состояние, затем сохраняет его. Интерфейс сообщает «сохранено» только после успешной записи.

При ошибке записи ранее сохранённое состояние не заменяется. Несохранённое изменение явно обозначается; доступны повтор записи и экспорт текущего состояния из памяти. Повтор записи сохраняет те же идентификаторы и не создаёт новые объекты.

Повреждённые данные при загрузке нельзя автоматически заменять пустым состоянием. Показывается ошибка, предлагается скачать исходное содержимое для восстановления либо явно сбросить данные. Сброс затрагивает только ключ приложения, а не всё хранилище браузера.

Пользовательский и импортированный текст выводится как текст, без исполнения HTML или JavaScript. Внешние запросы и внешние ресурсы отсутствуют. Демонстрационные данные загружаются только по явному действию в пустое состояние.

## 5. Данные и время

Все записи имеют постоянный уникальный идентификатор. Изменяемые основные объекты также имеют даты создания и изменения. Связи хранятся по идентификаторам.

| Объект | Состав |
|---|---|
| Сфера | Название, цвет, архив; недельный минимум в минутах или количестве действий |
| Цель | Название, сфера, описание, необязательный критерий результата и срок; активна, завершена или в архиве |
| Задача | Название, сфера, необязательная цель и длительность; дедлайн, разрешение деления, выполнена или не выполнена, архив |
| Занятие | Задача, дата, начало, конец, исходный объём в минутах, номер части, отметка выполнения |
| Встреча | Название, дата, начало и конец; создаётся только вручную |
| Привычка | Название, сфера, выбранные дни или недельная частота; периоды действия правил и паузы |
| Отметка привычки | Идентификатор привычки и местная дата; одна отметка на дату |
| Доступность | Интервалы по дням недели и заменяющие их исключения на даты |
| План недели | Понедельник недели, кандидаты и обязательные задачи, снимок условий, версия, статус, занятия и нарушения |
| Вариант | Режим, занятия, исключённые задачи с причинами, показатели, версия условий |
| История | Время операции, тип объекта, изменение, старое и новое назначение при переносе |
| Самочувствие | Дата, оценка 1-5, необязательная заметка |
| Шаблон | Название, копируемые задачи, относительные дни и время занятий |
| Предложение помощника | Название, сфера, цель, длительность, пояснение, идентификатор и состояние принятия |

Обязательность задачи относится к конкретной неделе. Просрочка вычисляется по дедлайну и не является статусом выполнения. План бывает черновиком или подтверждённым; нарушения учитываются отдельно.

Для упрощения расписание хранит местные даты `YYYY-MM-DD` и время `HH:mm`, без конвертации часовых поясов. Для определения сегодняшнего дня используется местная дата устройства. Настраиваемые часовые пояса отсутствуют. Смена зоны устройства не сдвигает сохранённые блоки, но может изменить текущую дату и оценку просрочки; работа при таких изменениях не входит в приёмку.

Временные блоки находятся внутри одного дня и не пересекают полночь. Многодневную встречу пользователь вводит отдельными блоками. Дедлайн без времени означает конец указанной местной даты.

Измеримый результат цели служит критерием. Достижение цели подтверждает пользователь; автоматический количественный прогресс цели не рассчитывается.

## 6. Правила планирования

### 6.1. Доступность и ограничения

- Можно задать несколько доступных интервалов на каждый день.
- Исключение полностью заменяет интервалы конкретной даты; пустое исключение означает недоступный день.
- Встречи блокируют соответствующее время.
- Начало блока должно быть раньше окончания. Отрицательные длительности и некорректные даты отклоняются.
- Автоматическое размещение использует шаг 15 минут. Настраиваемый промежуток по умолчанию - 15 минут.
- Между занятиями, а также занятием и встречей соблюдается промежуток. Между двумя встречами дополнительный промежуток не требуется.
- Занятия автоматически размещаются только в доступности, без пересечений и до дедлайна.
- Для текущей недели автоматическое размещение использует только будущее время. Прошлая неделя доступна для просмотра и ручного редактирования, но не для генерации.
- Предпочтительные интервалы сфер являются мягким условием. Их нарушение показывается отдельно.
- Ручное пересечение, выход за доступность или размещение после дедлайна разрешены только после показа причин и явного подтверждения. Некорректные поля таким подтверждением обойти нельзя.

### 6.2. Задачи и части

Задача может существовать без цели, даты или длительности. Без длительности она остаётся в списке, но не размещается автоматически. Перед генерацией пользователь выбирает кандидатов и обязательные задачи.

Деление разрешается отдельным флажком задачи. Минимальная автоматически создаваемая часть - 30 минут. Задача меньше 30 минут размещается целиком. Если корректное деление невозможно, задача рассматривается как неделимая либо остаётся с объяснением.

У каждой части отдельно хранятся исходный объём и занятый временной интервал, округлённый вверх до шага. Сумма исходных объёмов частей и незапланированного остатка равна объёму задачи. Например, задача на 50 минут может занимать 60 минут календаря, но в минимум сферы засчитываются 50 минут.

Удаление части возвращает её исходный объём в остаток, а не завершает задачу. Выполненные части сохраняются при переносе остальных. Уменьшить объём ниже уже выполненного нельзя - сначала требуется явно скорректировать отметки.

Выполнение всех частей полностью запланированной задачи предлагает завершить задачу. Отметка задачи целиком выполненной после предупреждения отмечает её существующие части. Отмена этой операции снимает только отметки, поставленные ею, сохраняя ранее выполненные части. Незапланированное выполнение задачи показывается в итогах отдельно от выполненных плановых часов.

### 6.3. Минимумы сфер

Минимум задаётся в плановых минутах либо самостоятельных действиях на неделю. Минуты считаются по исходному объёму занятий, без округления, встреч и промежутков.

Для количественного минимума одна полностью запланированная задача считается одним действием независимо от числа частей. Частично запланированная задача не считается полным действием. Привычка без занятия не добавляет часы или действия в минимум расписания.

Приложение не уменьшает минимум автоматически и не создаёт скрытые задачи для его достижения. Если нужных действий или времени недостаточно, показываются недостающий объём и соответствующие задачи.

### 6.4. Варианты недели

Используется простой детерминированный алгоритм последовательного размещения. Глобально оптимальное расписание и нахождение всех возможных решений не гарантируются. Если алгоритм не нашёл место, сообщение описывает результат текущего алгоритма, а не доказывает невозможность любого расписания.

Общий порядок для всех режимов:

1. сохранить встречи и выполненные занятия;
2. разместить оставшиеся обязательные действия;
3. добавить кандидатов для недостигнутых минимумов;
4. разместить необязательные действия по правилу выбранного режима.

При равном приоритете раньше выбирается ближайший дедлайн, затем постоянный порядок идентификаторов. Для минимумов сферы обходятся по постоянному порядку; после успешного добавления проверяется следующая недостигнутая сфера. Сначала ищется подходящий предпочтительный интервал, затем любой допустимый, в порядке даты и времени.

Предусмотрено до трёх режимов:

- сбалансированный - на шаге 4 раньше выбирается сфера с наименьшим плановым объёмом;
- рабочий - на шаге 4 раньше выбираются действия сферы, явно назначенной рабочей;
- восстановительный - на шаге 4 раньше выбирается назначенная сфера отдыха; необязательные действия добавляются, пока остаётся не менее 25% доступных минут после вычитания встреч. Проверка учитывает занятые интервалы и обязательные промежутки. Если обязательные действия и минимумы уже превышают этот порог, они не удаляются, а нарушение пожелания показывается.

Если рабочая сфера или сфера отдыха не назначена, соответствующий режим недоступен с объяснением. Одинаковые расписания объединяются; меньше трёх вариантов допустимо.

Каждый вариант проходит отдельную проверку. У исключённых задач показываются причины - нет длительности, недостаточно доступных минут, нет непрерывного окна, дедлайн или ограничение выбранного режима. Если точную причину нельзя установить, используется формулировка «не размещено текущим алгоритмом».

### 6.5. Подтверждение и изменения

Изменение влияющих на расписание данных увеличивает версию условий соответствующего плана. Старые варианты помечаются устаревшими. Перед подтверждением повторно проверяются версия условий и актуальное время. При неактуальных условиях выполняется повторная генерация либо явное редактирование и проверка.

Пользователь выбирает вариант, редактирует его и подтверждает. Неполный план можно подтвердить после просмотра конкретных нарушений. Исходные минимумы сохраняются.

При первом подтверждении создаётся неизменяемый снимок исходного плана, названий, объёмов и условий. Повторное подтверждение после правок не заменяет этот снимок. Текущий план и история хранятся отдельно.

Подтверждённый план изменяется только по явному действию пользователя. Генерация для его замены требует отдельного действия и не затрагивает выполненные занятия. Повторное нажатие подтверждения не создаёт дубликатов.

## 7. Ежедневное использование и история

### 7.1. Привычки и самочувствие

Привычка задаётся выбранными днями или числом выполнений за неделю. Она не резервирует время. Для занятия пользователь создаёт обычную задачу; автоматическая связь отметок задачи и привычки исключена из учебной версии.

Не более одной отметки привычки на дату. Повторное нажатие не увеличивает прогресс; отмена снимает отметку. Прошлые даты доступны, будущие запрещены. При режиме по дням отмечаются предусмотренные правилом дни вне периода паузы.

Изменение правила и пауза действуют с выбранной даты и не пересчитывают прошлые периоды. Для недельной частоты при создании, паузе или возобновлении посреди недели пользователь явно задаёт цель неполной недели. Она не может быть меньше уже зачтённых выполнений; полностью приостановленная неделя не имеет цели. Скрытого пропорционального пересчёта нет.

Самочувствие - одна оценка 1-5 и заметка на дату. Будущие даты запрещены; пропуск не считается нулём. Причины самочувствия автоматически не выводятся.

### 7.2. Перенос, копирование и архив

Перенос сохраняет идентификаторы задачи и занятия, старое и новое назначение в истории. В исходной неделе остаются снимок и факт переноса, в новой появляется активное занятие. Выполненное занятие переносится только после отдельного предупреждения.

Копирование недели создаёт новые задачи и занятия, сбрасывает выполнение, не копирует самочувствие, отметки привычек и историю. Встречи по умолчанию не копируются; их можно включить явно. Для копируемых задач с дедлайном требуется задать новый дедлайн либо исключить задачу. Конфликты целевой недели показываются до сохранения. Копия всегда является черновиком.

Шаблон сохраняет структуру задач и относительные дни/время занятий. Применяется тот же механизм копирования с новыми идентификаторами. Встречи в шаблон не входят. Повтор сохранения одной операции не создаёт вторую копию.

Архив цели не удаляет её задачи. При архивировании сферы с активными задачами требуется их переназначить либо исключить из будущего планирования. Обычное удаление задачи означает архивирование и отмену её невыполненных будущих занятий с записью в истории. Выполненные занятия и исходные снимки сохраняются.

Изменение общего минимума применяется к новым планам. Изменение условий уже созданной недели является отдельным действием с историей. Итоги прошлых недель используют их собственные снимки.

### 7.3. Итоги

Показываются исходный подтверждённый план, текущий план, выполнение, минимумы сфер, привычки, переносы и оценки самочувствия. У выполненных занятий суммируется исходная плановая длительность. Термин «фактическое время» не используется.

Просмотр итогов не требует операции «закрыть неделю». Поздние изменения не переписывают исходную базу сравнения.

## 8. Учебный помощник без API

Безопасный обязательный вариант - локальный помощник на правилах и заранее заданных шаблонах внутри `script.js`. Он не является ИИ-моделью и обозначается в интерфейсе как «учебный помощник на шаблонах, без ИИ».

Пользователь выбирает тип цели, например работа, спорт, творчество или отдых. Помощник задаёт до трёх подготовленных вопросов и предлагает редактируемые действия с названием, сферой, длительностью и пояснением связи с целью. При пропуске ответа показываются принятые допущения. Для собственной цели без подходящего шаблона используется ручной ввод.

Предложения существуют отдельно от задач. Пользователь принимает каждое предложение либо отклоняет его. Повторное принятие не создаёт вторую задачу. Принятые задачи не включаются в кандидаты и не размещаются без явного действия пользователя. Планировщик работает независимо от помощника.

В приложении нет полей API-ключа, запросов к поставщику, скачивания модели или скрытой передачи данных. Размещение секретного ключа в JavaScript либо localStorage не принимается как решение. Риск раскрытия ключей в клиентском окружении описан в [официальных рекомендациях OpenAI](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety).

Необязательный вариант дальнейшего учебного расширения - подготовить текст запроса для ручного копирования в отдельно открытый ИИ-чат и вручную перенести результат в формы. Это не интеграция приложения, не входит в приёмку и не отправляет данные автоматически. Пользователь сам выбирает сведения для передачи; встречи и заметки самочувствия не включаются по умолчанию. Автоматический разбор ответа внешнего ИИ в этой версии не требуется.

## 9. Интерфейс

Все разделы находятся в одном HTML-документе; переходы переключают представления без загрузки отдельных страниц.

| Раздел | Основные элементы |
|---|---|
| Сегодня | Встречи и занятия, привычки, невыполненные и просроченные задачи, самочувствие |
| Неделя | Семь дней, время, встречи, занятия, доступность, остаток задач, минимумы, предупреждения |
| Подготовка недели | Доступность, исключения, встречи, кандидаты, обязательность, минимумы, предпочтения |
| Варианты | До трёх расписаний, показатели, причины исключения, редактирование и подтверждение |
| Цели и задачи | Формы, поиск, фильтры, части, выполнение, архив и учебный помощник |
| Привычки | Правила, отметки недели, прогресс, пауза, возобновление и архив |
| История и итоги | Исходный и текущий планы, выполнение, переносы, самочувствие, копирование |
| Настройки | Сферы, доступность, промежутки, предпочтения, назначение рабочих/восстановительных сфер, шаблоны, JSON-экспорт/импорт и сброс |

Подготовка и варианты являются шагами раздела «неделя». Есть переход к текущей неделе и смена выбранной даты. В шапке отображается состояние сохранения. Вход, выход и индикаторы внешних интеграций отсутствуют.

Формы имеют подписи, видимый фокус и управление клавиатурой. Цвет сферы дублируется текстом. Длинные названия не перекрывают кнопки. Предусмотрены пустые состояния, ошибки, предупреждения и результат операции. Ошибка загрузки не отображается как пустой список.

Кнопка выполнения и её отмена доступны из карточек. Для переноса используется форма с датой и временем; изменение объёма задачи является отдельной операцией.

## 10. Ручной JSON-экспорт и импорт

### 10.1. Экспорт

По кнопке приложение скачивает один JSON-файл со всеми данными - версия формата, дата выгрузки, настройки, сферы, цели, задачи, занятия, встречи, привычки и их правила/отметки, планы и снимки, история, самочувствие, шаблоны и предложения помощника.

При несохранённых изменениях экспортируется текущее состояние памяти с явной пометкой в интерфейсе. Экспорт не запускается по расписанию и не является синхронизацией. Пользователь отвечает за хранение файла вне браузера. JSON не шифруется; это указывается рядом с кнопкой выгрузки.

### 10.2. Импорт

Импорт полностью заменяет состояние, объединение копий не поддерживается. Порядок:

1. прочитать выбранный файл в память;
2. проверить JSON, версию, обязательные поля, типы, диапазоны, идентификаторы и ссылки;
3. проверить согласованность объёмов частей, дат, отметок и снимков;
4. показать количество объектов и предупреждение о полной замене;
5. предложить скачать текущие данные и потребовать подтверждения, что копия сохранена, либо явного отказа от неё;
6. после подтверждения записать проверенное состояние одной операцией в ключ приложения;
7. только после успешной записи заменить отображаемые данные.

Валидные сохранённые нарушения расписания допускаются - ручные пересечения не считаются повреждением структуры. Неподдерживаемая версия, дубликаты идентификаторов, неизвестные ссылки и некорректные значения отклоняются до замены.

Частичный импорт запрещён. При отмене или ошибке чтения, проверки либо записи исходное состояние сохраняется. Перед импортом несохранённые изменения также включаются в предлагаемую страховочную выгрузку. Наличие скачанного файла на диске приложение не проверяет; оно получает подтверждение пользователя.

Импортированное состояние должно быть пригодно для повторного экспорта с сохранением идентификаторов, связей и исходных снимков.

## 11. Этапы разработки

Каждый этап завершается запускаемым результатом и проверкой. Изменяются только три файла приложения. Решения фиксируются в этом ТЗ и отчёте этапа; отдельный обязательный `AGENTS.md`, конфигурация или файл тестов не добавляются. Следующий этап начинается после устранения блокирующих ошибок предыдущего.

| Этап | Результат | Обязательная проверка |
|---|---|---|
| 0. Среда и границы | Зафиксированы браузер, ОС, способ запуска, три файла и правила | localStorage сохраняется после закрытия и повторного открытия по тому же пути; ограничения режима запуска описаны |
| 1. Интерфейс | Все разделы, формы и пустые состояния | Ширины 1280/1920, клавиатура, длинные названия, переходы |
| 2. Модель и хранение | Проверка данных, загрузка, сохранение, ошибки | Повторное открытие, неверные значения, повреждённое состояние, отказ записи |
| 3. Ручное планирование | Сферы, цели, задачи, доступность, встречи, части и календарь | Несколько окон, исключения, деление, остаток, перенос, предупреждения |
| 4. Варианты и подтверждение | Независимая проверка, три режима, снимок и версии | Минимумы, дедлайн, разорванное окно, одинаковые варианты, текущая неделя, устаревшие условия |
| 5. Ежедневная работа | Выполнение, привычки, самочувствие, история и итоги | Повтор отметки, отмена, пауза, прошлые правила, неизменность снимка, ручной подсчёт итогов |
| 6. Повторное использование | Копирование, шаблоны и учебный помощник | Новые идентификаторы, сброс выполнения, дедлайны, конфликты, отсутствие дубликатов принятия |
| 7. Переносимость данных | Экспорт, проверка и замена через импорт | Полный цикл, повреждённый файл, неподдерживаемая версия, неизвестные ссылки, ошибка записи |
| 8. Приёмка | Проверены все сценарии, инструкция запуска внутри интерфейса | Три файла, работа без сети, перезапуск, отсутствие внешних подключений и блокирующих ошибок |

Контрольные примеры готовятся до реализации алгоритма. Содержательные проверки планировщика, объёмов, истории и импорта можно разместить в отдельной тестовой функции внутри `script.js`, запускаемой явно и не меняющей личные данные. Она не запускается при обычном открытии. Внешние файлы тестов в поставку не входят.

Ориентир производительности для зафиксированной среды - генерация одной недели со 100 кандидатами не более 5 секунд. Это требование, а не заявленный результат. Контрольный набор включает 7 дней, до 2 окон в день, 20 встреч и разрешённое деление задач. Состав и длительности набора фиксируются перед этапом 4; в отчёте указывается измеренное время и среда. Оптимизация выполняется только при фактическом превышении.

## 12. Сценарии приёмки

| Сценарий | Ожидаемый результат |
|---|---|
| Три файла и отсутствие сети | В папке приложения только `index.html`, `style.css`, `script.js`; оно работает при отключённой сети, внешних запросов нет |
| Полная неделя | Цель, задачи, встречи и ограничения позволяют выбрать, поправить и подтвердить план; повторное открытие сохраняет данные |
| Недостижимый минимум | Требуются две тренировки, помещается одна; исходный минимум не изменяется, нарушение видно перед подтверждением и в итогах |
| Разорванная доступность | Три окна по 30 минут не вмещают неделимую задачу на 90 минут; она остаётся с причиной отсутствия непрерывного окна |
| Деление и округление | Исходный объём частей и остатка равен объёму задачи; округление не увеличивает минимум; части не считаются отдельными действиями |
| Удаление части | Выполненная часть сохраняется, удалённая возвращается в остаток, задача сама не завершается |
| Ручной конфликт | Перенос на встречу показывает конфликт; отмена сохраняет прежнее назначение, подтверждение сохраняет новое и предупреждение |
| Дедлайн и текущая неделя | Автоплан не ставит занятия после дедлайна или в уже прошедшее время; перед подтверждением время проверяется снова |
| Варианты | При равных условиях результаты воспроизводимы; одинаковые варианты объединены, режимы соблюдают заданные приоритеты |
| Изменение условий | Старый вариант обозначен как устаревший и не подтверждается без актуальной проверки |
| Подтверждённая неделя | Открытие страницы, работа помощника и изменение общих настроек не перестраивают занятия |
| Перенос | Идентификаторы сохранены, активное занятие одно, старое назначение есть в истории и исходном снимке |
| Копирование и шаблон | Созданы новые идентификаторы, отметки сброшены, источник не изменён, дедлайны согласованы явно |
| Выполнение и отмена | Завершение задачи не теряет ранее выполненные части; отмена общей отметки сохраняет независимые отметки |
| Привычки | Повторная отметка не удваивает результат, будущая дата запрещена, пауза и изменение правил не переписывают прошлые недели |
| Самочувствие | Оценка 1-5 сохраняется на выбранную дату; отсутствие записи не превращается в ноль |
| Итоги | Ручной расчёт контрольной недели совпадает с показателями; исходный план не меняется после позднего переноса |
| Учебный помощник | Режим честно обозначен, принятие создаёт одну задачу, без подходящего шаблона работает ручной ввод, API и ключей нет |
| Ошибка хранения | Видна ошибка; нет ложного «сохранено», прежняя запись сохранена, текущее состояние можно выгрузить |
| Полный цикл JSON | Экспорт, замена состояния и импорт восстанавливают настройки, объекты, связи, отметки, историю и снимки |
| Некорректный импорт | Ошибка JSON, неверная версия, дубликаты или неизвестные связи не меняют текущие данные |
| Отмена и сбой импорта | Отмена и отказ записи сохраняют исходное состояние целиком |
| Текст из файла | HTML-подобный текст показывается как текст и не исполняется |

Учебная версия принята после прохождения этих сценариев в зафиксированной среде и устранения блокирующих ошибок. Реальные ИИ-запросы, внешние календари, Telegram, вход и работа при закрытой странице не являются критериями готовности.

## 13. Постановка задач нейросети

Для реализации каждого этапа используется ограниченное поручение:

> Выполни только этап [номер и название] по этому ТЗ. Сначала изучи текущие index.html, style.css и script.js. Сохрани структуру строго из трёх файлов, обычные HTML/CSS/JavaScript и работу без внешних запросов. Не добавляй сервер, зависимости, ключи или интеграции. Реализуй результат этапа, проверь его сценарии и сообщи фактические результаты. Если проверка не запускалась, укажи «не проверено». Перечисли изменённые файлы, действия ручной проверки и оставшиеся проблемы. Не выполняй следующий этап.

Перед задачей передаются контрольные данные и ожидаемое поведение. Проверки оценивают результат, а не повторяют реализацию. Рабочее состояние сохраняется после принятого этапа. Неопределённое правило обсуждается и фиксируется до реализации зависимой функции.
